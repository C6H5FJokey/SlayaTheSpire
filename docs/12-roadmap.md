# 12 路线图

v1 之后的扩展方向。每条都标注了**已经预留的接口**，说明为什么现在不做不会返工。

## 1. 虚拟思考链

**动机**：Laya 没有思维链，但「提供更多思考信息 -> 更准」的原理可以用**分阶段类型化问题**复现。把一个大判断拆成若干先导判断题，把带概率的答案拼回 state，再问动作题。

**已预留**：`decision_points.toml` 的 `prelude` 段（见 [06-decision-points](06-decision-points.md#虚拟思考链v1-关闭钩子已留)）；数据集行的 `prior` 字段。

**要做的事**：

- 为每个决策点设计先导题（战斗：最大威胁 / 能否斩杀 / 本回合能量取舍；地图：生存压力 / 成长需求）；
- 两段式请求（先 prelude 并行问，再拼回 state 问动作）；
- 用采集数据做 A/B：**同一批 state 跑「有 prelude」与「无 prelude」两遍，比人类一致率与胜率**。

**成本**：每题一次 forward（GPU 上几十毫秒），但请求数翻倍。

## 2. OCR / 无模组通道（computer use）

**动机**：不依赖模组，用截图 + OCR 识别状态、用鼠标键盘注入动作。可迁移到不能装模组的场景。

**已预留**：`ObservationSource` / `ActionSink` 两个 Protocol（`spire-agent`），本版只有 mod 实现。

**难点（诚实评估）**：

- **状态识别精度**：牌的升级状态、powers 层数、意图数值都是小字，OCR 误差会直接变成错误决策；
- **代价函数的安全**：鼠标注入无法像 mod 那样做白名单校验，误点击可能直接结束回合或买错东西；需要"点击前校验 UI 状态"的闭环；
- **与 Laya 的关系**：Laya 是文本判断模型，不具备视觉能力。所以 OCR 通道**必须**先把像素变成结构化文本，Laya 才用得上；若想跳过 OCR 直接用视觉模型，那是另一条技术栈（与 Laya 无关）。

**建议顺序**：先做**只读** OCR（识别 + 落盘 + 与 mod 数据交叉校验），验证识别率；确认稳定后再做动作注入。

## 3. 微调流程

**动机**：官方 checkpoint 是通用判断模型，不懂"这张牌在这个卡组里值多少"。

**已预留**：`dataset/*.jsonl` 直接就是 `(state, questions) -> answer` 三元组，无需重建。

**流程**：

1. **采集**：`observe_human` 模式跑足够多的人类对局（强标签）；`agent` 模式跑自博弈（弱标签，配合 `outcome` 用）。
2. **清洗**：`export.py --verify` 保证确定性；按 `match_rate` 排查候选枚举缺口；按 `by_decision_point` 排查采集偏斜（例如商店样本过少就专门多跑几局）。
3. **切分**：按 run 切分（已内建），train/val/test 不共享任何一局。
4. **训练**：加载官方 checkpoint（`laya-typed-decisions` 或 `english`）作为起点，按 Laya 官方的微调接口训练。**具体训练格式以实现时 Laya 仓库的 finetune 文档为准**（本仓库只负责产出兼容数据，不硬编码训练细节）。
5. **评测**：
   - 离线：留出集上的 answer accuracy、校准（`answer_confidence` 与正确率是否吻合）、延迟；
   - 在线：用 `observe_human.also_query_model = true` 得到的 `agreement_rate` 作为主指标——**"模型与人类一致率"比"胜率"噪声小得多，适合快速迭代**；
   - 最后才看胜率（需要固定种子成组对比）。
6. **上线**：微调后的 checkpoint 通过 `laya.model` 指定的路径加载（Laya 支持 `model_id_or_path`），逐局对比。

**注意**：`post_sl` 房间与 `agent_fallback` 行默认排除——它们要么标签被污染，要么根本没有模型参与。

## 4. 并发多局

**动机**：采集效率。单局 40 分钟，一天跑不了几局。

**已预留**：`spire-agent` 的单事件循环架构（把 `run_loop` 变成 per-run 任务即可）；mod 支持多连接（踢掉旧的）。

**要解决**：多开游戏实例（Steam 家庭共享/多份拷贝）、每实例独立端口、`runs/<run_id>` 隔离、Laya 并发上限（`LAYA_MAX_CONCURRENT`，超出会 503，需要排队）。

## 5. 地图问法的对比实验

**动机**：地图是 DAG 上的逐步决策，「只描述下一层节点」可能不是最优问法。

**已预留**：`serialize/map.py` 的描述函数独立成模块。

**对比方案**：

- A（当前）：逐步选节点 + 下游 2-3 层摘要；
- B：规则枚举到 Boss 的代表性完整路线，让模型选整条路线；
- C：对每个候选节点分别 `score`（生存价值 / 成长价值两题再加权）。

用同一批人类对局做离线对比（看 `agreement_rate`），不需要重新采集。

## 6. noul 展开训练

**已预留**：`dataset.expand_choice_to_noul()`（见 [08-dataset](08-dataset.md#一次采集两种问答形态)）。

把 `choice` 行无损展开成 N 条 `noul` 行，得到均衡的二分类样本。适合用来**单独训一个"该不该做 X"的判断器**，或者做数据增强（同一个 `state` 出现 N 次，但每次问不同的候选）。

## 7. 更多角色与进阶

v1 只跑 Ironclad / Ascension 0。扩展时要注意：

- 角色的**专属机制**（静默的毒/弃牌、机器的充能球、观者的姿态）需要在序列化里显式表达（`orbs`、姿态等字段）；
- 进阶等级会影响敌人配置与数值，`context.ascension` 已落盘，可分组训练/评测；
- 不同角色的牌池差异大，**不建议混训**——先分别采集与评测，再决定是否多任务。
